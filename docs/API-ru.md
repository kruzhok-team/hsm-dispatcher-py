# Спецификация интерфейса диспетчера HSM для Python

Версия документа: 0.2 (2026-10-26)

Документ предназначен авторам программ, исполняющих машины состояний на
диспетчере, авторам диаграмм, которые эти программы исполняют, и авторам
типов компонентов. В нём описано всё, чем они пользуются: `Dispatcher`, код
диаграммы, машина, написанная на Python, стандартные компоненты, события
времени, собственный тип компонента, ошибки и сессия, предоставляющая машину
редактору для пошагового исполнения. Правила исполнения и их обоснование
приведены в `ARCHITECTURE.md`; hsm-to-python порождает программы,
использующие этот интерфейс.

```
 программа                            hsmd                          диаграмма
 ─────────                            ────                          ─────────
 Dispatcher(source, ...)  ──────────▶ модель ◀─────── документ (CyberiadaML) или
 start() post() run() send() tick()   очередь          объявления hsmd.Machine(...)
 states() finished() snapshot()       компоненты ────▶ Timer, Clock, Console, Log,
      ▲                                    │               типы программы
      └──── исходы, трассировка ◀──────────┘  ◀──── сигналы <id>.<SIGNAL>
```

Всё импортируется из одного модуля: `import hsmd`.

## Соглашения

* У **события** есть имя, приоритет и именованные параметры. Имена пишутся
  заглавными буквами с подчёркиванием между словами: `GO`, `DOOR_OPENED`.
  Диспетчер сравнивает их в том виде, в каком они записаны.
* **Компонент** объявляется в использующей его машине, одно объявление на
  экземпляр, формальным комментарием `CGML_COMPONENT <id>` (ПНСТ 1044, 10.3)
  с параметрами `type`, необязательными `priority` и `shared` и параметрами
  своего типа:

  ```
  CGML_COMPONENT blink
  type/ Timer

  priority/ 10
  ```

  Идентификатор компонента (`blink`) уникален в своей машине; `id` узла
  комментария уникален в документе, как и у любого узла.
* **Сигнал** `S` компонента `c` — это событие `c.S`; переход указывает его
  как триггер: `blink.TIMEOUT/`.
* **Метод** вызывается из кода: `blink.start(500)`; **переменная** читается:
  `[blink.difference < 100]`.
* **Приоритет** упорядочивает ожидающие события: сначала более высокий,
  равные — в порядке поступления. Событие программы имеет приоритет 0,
  сигнал — приоритет своего компонента.
* Компонент бывает **локальным** (экземпляр в каждой объявившей его машине,
  его сигналы идут этой машине) или **общим** (один экземпляр в документе под
  одним идентификатором и типом, его сигналы идут всем машинам). Это решает
  тип, `shared/ yes` или `shared/ no` переопределяет.
* **Время:** часы и календарь — секунды (числа с плавающей точкой), `period` —
  секунды, `Timer` считает миллисекунды.

## Диспетчер

```python
import time

import hsmd

dispatcher = hsmd.Dispatcher('blinker.graphml', period=0.1)
dispatcher.start()
outcome = dispatcher.send('button.PRESSED', long=True)
print(outcome.status, dispatcher.states())
while not dispatcher.finished():
    dispatcher.tick()                    # события времени, таймеры, консоль
    time.sleep(0.1)
```

### `Dispatcher(source, clock=None, trace=None, output=None, machines=None, namespace=None, period=None, calendar=None, input=None, timers=True)`

| Параметр | Значение |
|---|---|
| `source` | путь к документу CyberiadaML, либо `hsmd.Machine` или их список |
| `clock` | функция, возвращающая секунды монотонных часов; `time.monotonic` |
| `trace` | функция, вызываемая с каждой записью трассировки (кортежем); без неё трассировки нет |
| `output` | поток сообщений `Log`; `sys.stderr` |
| `machines` | идентификаторы или имена исполняемых машин; все машины |
| `namespace` | словарь, в котором исполняется код машин; новый |
| `period` | секунды: `tick()` посылает события времени; без него их нет |
| `calendar` | функция, возвращающая календарное время в секундах эпохи, для `Clock`; `time.time` |
| `input` | поток для `Console`; `sys.stdin` |
| `timers` | `False`: никаких событий от времени - `tick()` не посылает событий времени, `Timer` и `Clock` не выдают сигналов; их приносит записанный журнал (см. Сессии); `True` |

Конструктор загружает документ (или строит объявленные машины), проверяет
их, создаёт компоненты и компилирует код; проблема — это `DocumentError`.
До `start()` ничего не исполняется. Программа, записавшая код своей машины
функциями, передаёт свои глобальные имена как пространство имён:
`namespace=globals()`.

### Методы

| Метод | Возвращает | Делает |
|---|---|---|
| `start()` | исходы | входит в начальную конфигурацию каждой машины, обрабатывает очередь |
| `post(name, priority=0, machine=None, **parameters)` | `Event` | ставит событие в очередь, для всех машин или для указанной |
| `run()` | исходы | обрабатывает очередь, пока она не опустеет |
| `send(name, **parameters)` | `Outcome` события | `post()` и `run()` |
| `step()` | `Outcome` или `None` при пустой очереди | берёт одно событие из очереди в порядке `run()` и обрабатывает его |
| `tick(run=True)` | исходы | посылает наступившие события времени, даёт каждому компоненту проверить часы, `run()`; при `run=False` события остаются в очереди для `step()` |
| `states(machine=None)` | список идентификаторов состояний | активные состояния, начиная с внешнего |
| `finished(machine=None)` | `bool` | достигла ли машина конечного состояния |
| `triggers(machine=None)` | список имён | триггеры активных состояний, ограждающие условия не вычисляются |
| `comments(machine=None, formal=True)` | пары `(name, body)` | комментарии, которые диспетчер не интерпретирует: формальные, неформальные (`False`, имя пустое) или оба вида (`None`) |
| `snapshot()` | словарь простых данных | состояние исполнения |
| `restore(data)` | | продолжает со снимка, снимает остановку |

Машина указывается идентификатором или именем; без него имеется в виду
первая машина. `stopped` истинно после ошибки (см. «Ошибки»).

### `Event` и `Outcome`

`Event`: `name`, `priority`, `parameters` (словарь), `machine` (адресат,
`None` для всех машин). Параметры доступны и как атрибуты: `event.speed`;
отсутствующий параметр — это `AttributeError`.

`Outcome`: `event`, `status`, `transitions` (идентификаторы выполненных
переходов) и `results` (по одному на машину: `machine`, `status`,
`transitions`). Статус:

| Статус | Константа | Значение |
|---|---|---|
| `fired` | `hsmd.FIRED` | выполнен один или несколько переходов |
| `deferred` | `hsmd.DEFERRED` | событие отложено состоянием |
| `rejected` | `hsmd.REJECTED` | триггер совпал, все ограждающие условия ложны |
| `dropped` | `hsmd.DROPPED` | ни один триггер не совпал |

В исходы `run()` входят и события завершения; их имя пустое.

### Трассировка

Функция трассировки получает кортеж, первым идёт вид записи:

| Запись | Когда |
|---|---|
| `('post', name, priority[, machine])` | событие поставлено в очередь |
| `('event', name)` | событие взято из очереди |
| `('guard', machine, transition, text, value)` | вычислено ограждающее условие (`text` — имя функции условия) |
| `('fire', machine, transition)` | выполнен переход |
| `('exit', machine, state)`, `('enter', machine, state)` | выход из состояния, вход в него |
| `('completion', machine, state)` | порождено событие завершения |
| `('defer', machine, transition)` | событие отложено |
| `('history', machine, pseudostate, state)` | псевдосостояние истории восстановило состояние |
| `('ambiguous', machine, chosen, others)` | разрешены несколько переходов |
| `('terminated', machine)`, `('finished', machine)` | завершение, конечное состояние |
| `('print', component, line)` | сообщение `Log` |
| `('outcome', machine, status, transitions)` | результат шага |
| `('error', message)` | диспетчер остановлен |

Внутренний переход называется `<state>#<n>`, элемент встроенной подмашины —
`<state>/<identifier>`.

### Снимок

`snapshot()` возвращает версию формата, конфигурацию и историю каждой
машины, очередь, отложенные события и данные компонентов в виде простых
данных (JSON сохраняет их, если параметры событий тоже простые).
`restore(data)` продолжает с него в том же диспетчере или в новом с теми же
машинами. Снимок берут после `run()`, когда очередь пуста. Таймер сохраняет
оставшееся время, часы — свой будильник; у консоли снимка нет.

## Код диаграммы

Поведение состояния или перехода — это операторы Python, ограждающее
условие — выражение. Им видны:

* компоненты машины по идентификаторам: `blink.start(500)`;
* `event`, обрабатываемое событие: `event.name`, `event.speed`;
* имена пространства имён (`namespace=`): функции и переменные программы.
  Имя, которому код присвоил значение, остаётся в пространстве имён и видно
  последующему коду машины.

```
entry/
blink.start(500)

GO [event.speed > 3]/
log.print('going at', event.speed)

blink.TIMEOUT/
led = not led

[else]/
```

Триггер `ANY` совпадает с любым событием, которое называет какой-либо
триггер машины, `UNKNOWN` — с событием, которое не называет ни один;
`ANY` внутреннего состояния скрывает обработчики объемлющих состояний, если
не помечен `propagate`. `[else]` — ограждающее условие пути, выбираемого,
когда не выполнено ни одно другое условие того же триггера. События времени
описаны ниже.

Код может быть и функциями Python (см. следующий раздел): функция
вызывается без аргументов и работает в глобальных именах своего модуля,
поэтому программа передаёт их как пространство имён; имена, которым она
присваивает значения, объявлены `global`. Ошибка в коде — это `ActionError`
с элементом и строкой блока.

## Машина, написанная на Python

Программа может объявить свою машину вместо загрузки документа: код — это
функции, структура — дерево объявлений. Действуют правила документа, а ни
файл, ни `CyberiadaML` не нужны.

```python
import hsmd


def idle_entry():
    log.print('idle')


def go_guard():
    return event.speed > 3


machine = hsmd.Machine('Robot', id='R', states=[
    hsmd.Initial(id='init'),
    hsmd.State('Idle', id='idle', entry=idle_entry, internal=[
        hsmd.On('PING', action="log.print('pong')"),
    ]),
    hsmd.State('Work', id='work', states=[
        hsmd.Initial(id='work-init'),
        hsmd.State('Step', id='step'),
    ]),
    hsmd.Final(id='fin'),
], transitions=[
    hsmd.Transition('init', 'idle'),
    hsmd.Transition('idle', 'work', 'GO', guard=go_guard),
    hsmd.Transition('work-init', 'step'),
    hsmd.Transition('work', 'fin', 'STOP'),
], components=[
    hsmd.Declaration('log', 'Log'),
])

dispatcher = hsmd.Dispatcher(machine, namespace=globals())
```

| Объявление | Значение |
|---|---|
| `Machine(name, id=None, states=(), transitions=(), components=(), transition_order='actionFirst', propagate=False, comments=())` | машина состояний; комментарии — пары `(name, body)`, имя пустое у неформального |
| `State(name, id=None, entry=None, exit=None, internal=(), states=())` | состояние, составное при `states`; `entry`, `exit` — один фрагмент кода или список |
| `Initial(id=None)`, `Final(id=None)`, `Terminate(id=None)` | псевдосостояния и конечное состояние |
| `Choice(id=None, name='')`, `History(id=None, deep=False)` | выбор, неглубокая или глубокая история |
| `EntryPoint(name, id=None)`, `ExitPoint(name, id=None)` | точки состояния или машины |
| `On(event, guard=None, action=None, propagate=None, defer=False)` | внутренний переход своего состояния |
| `Transition(source, target, event='', guard=None, action=None, propagate=None, defer=False, id=None)` | переход между вершинами, указанными идентификаторами |
| `Declaration(id, type, priority=None, shared=None, **parameters)` | компонент |
| `ELSE` | ограждающее условие `[else]` |

Ограждающее условие или действие — функция или текст. Опущенные
идентификаторы: у машины и состояния — имя; у псевдосостояния —
`<parent>.<kind>` (у точки — `<parent>.<name>`); у внутреннего перехода —
`<state>#<n>`; у перехода — `<source>-<target>`, `#2`, `#3` для следующих с
теми же концами. `propagate=None` — значение машины по умолчанию.
Объявление, нарушающее правила, — это `DocumentError` от `Dispatcher`.

## Стандартные компоненты

### Timer

Локальный. Считает миллисекунды по часам диспетчера.

* Сигналы: `TIMEOUT` — интервал истёк; повторяется каждый интервал или
  приходит один раз после `once()`.
* Методы: `start(interval)` — периодический; `once(interval)` — один
  `TIMEOUT`, затем таймер выключен (`start()` снова делает его
  периодическим); `reset()` — отсчитать интервал заново; `enable()`,
  `disable()` — продолжить и остановить, сохраняя оставшееся время.
* Переменные: `interval`, `enabled`, `difference` — время до следующего
  `TIMEOUT`.

Запоздавший `tick()` порождает один `TIMEOUT`; следующий интервал
отсчитывается от него.

```
entry/
blink.start(500)
deadline.once(10000)

deadline.TIMEOUT/
log.print('too late')
```

### Clock

Локальный. Календарное время диспетчера (`calendar=`) в местном времени.

* Сигналы: `ALARM` — местное время совпало с полями будильника.
* Методы: `alarm(hour=None, minute=0, second=0)` — звонить в каждый момент
  местного времени с этими полями, `None` — любое значение; `cancel()`.
* Переменные: `now` (`datetime`), `hour`, `minute`, `second`, `weekday`
  (0 — понедельник).

| Вызов | Звонит |
|---|---|
| `alarm(9)` | каждый день в 09:00:00 |
| `alarm(9, 30)` | каждый день в 09:30:00 |
| `alarm()` | каждый час в чч:00:00 |
| `alarm(minute=None)` | каждую минуту в чч:мм:00 |

Запоздавший `tick()` порождает один `ALARM`, следующий — в ближайший
подходящий момент; переход на летнее время учитывается.

```
entry/
morning.alarm(9)

morning.ALARM [morning.weekday < 5]/
log.print('a working day', morning.now.date())
```

### Console

Общий: один ввод на документ. Строки потока `input` диспетчера
(`sys.stdin`) в UTF-8, опрашиваемые `tick()` без блокировки.

* Сигналы: `LINE(text)` — строка, `event.text` без перевода строки; `EOF` —
  один раз, после последней строки (последняя строка без перевода строки
  сначала приходит как `LINE`).
* Переменные: `last` — последняя прочитанная строка; если один `tick()`
  прочитал несколько строк, она опережает событие, поэтому переход читает
  `event.text`.

В Windows читается только клавиатура консоли, перенаправленный ввод — нет.

```
console.LINE [event.text == 'quit']/
log.print('bye')

console.EOF/
```

### Log

Локальный. Методы: `print(*values)` — одна строка в поток `output`
диспетчера (`sys.stderr`) и запись `print` трассировки. Сигналов нет.

## События времени

При заданном `period` (секунды) `tick()` посылает события времени, на
которые реагируют запущенные машины, отсчитывая их от `start()` по часам
диспетчера (`hsmd.TIME_EVENTS`):

| Событие | Каждые |
|---|---|
| `TIME_TICK` | период |
| `TIME_TICK_1S` | секунду |
| `TIME_TICK_1M` | минуту |
| `TIME_TICK_1H` | час |

Они остаются на целых периодах от старта: запоздавший `tick()` посылает
каждое один раз и пропускает упущенные; `restore()` начинает отсчёт заново.
Событие, которого не называет ни один триггер, не посылается, поэтому
`ANY` и `UNKNOWN` их не видят. Час по часам (`чч:00`) — это будильник
`Clock`, интервал, который машина запускает и останавливает, — `Timer`.

## Собственный тип компонента

Тип компонента — это подкласс `hsmd.Component`, зарегистрированный под
именем, которое объявления указывают как `type`. Компонент нужен только
типу, который порождает события или нуждается в диспетчере: счётчик или
список — это обычный Python.

```python
import hsmd


class Battery(hsmd.Component):
    """The charge level; LOW once when it falls under the threshold."""

    signals = {'LOW': ('level',)}
    variables = ('level',)

    def __init__(self, ident, dispatcher, **parameters):
        hsmd.Component.__init__(self, ident, dispatcher, **parameters)
        self.threshold = int(parameters.get('threshold', 20))
        self.level = 100

    def drain(self, amount):
        self.level = max(0, self.level - amount)
        if self.level < self.threshold:
            self.signal('LOW', level=self.level)

    def snapshot(self):
        return {'level': self.level}

    def restore(self, data):
        self.level = data['level']


hsmd.register('Battery', Battery)
```

```
CGML_COMPONENT battery          entry/                 battery.LOW/
type/ Battery                   battery.drain(7)       log.print('low', event.level)

threshold/ 20
```

| Элемент | Значение |
|---|---|
| `Component(ident, dispatcher, **parameters)` | конструктор, который сохраняет тип; параметры объявления приходят строками |
| `id`, `dispatcher`, `parameters`, `machine` | идентификатор, диспетчер, параметры, идентификатор машины-владельца (`None` у общего) |
| `priority`, `shared` | значения типа по умолчанию: приоритет его сигналов, видимость |
| `signals` | сигнал -> имена его параметров; `None`, если не объявлены (тогда проверки инструментов принимают любой) |
| `variables` | имена, которые читает код |
| `signal(name, **parameters)` | породить событие `<id>.<name>` |
| `tick(now)` | вызывается `Dispatcher.tick()` со значением часов; здесь проверяются сроки |
| `snapshot()`, `restore(data)` | данные компонента в снимке; простые данные |

Методы типа — его открытые функции. Метод выполняется внутри шага: он
возвращается сразу, а длительную работу метод запускает и сообщает о её
окончании сигналом из `tick()`. `hsmd.describe(cls)` даёт объявленный
интерфейс: `{'methods': {name: [parameters]}, 'variables': [...],
'signals': {...} или None}`. Тип регистрируется до того, как диспетчер
загрузит машины.

## Ошибки

| Ошибка | Когда |
|---|---|
| `hsmd.DocumentError` | документ или объявления нарушают правило, тип компонента неизвестен, в коде синтаксическая ошибка; порождается конструктором |
| `hsmd.ActionError` | код упал при исполнении; `where` (машина, элемент, блок), `line` (строка блока), `error` (исключение) |
| `hsmd.ExecutionError` | машина не может продолжать: у выбора нет истинной ветви, составное состояние без начального псевдосостояния вошли по умолчанию |
| `hsmd.StoppedError` | вызов остановленного диспетчера |

Все они — подклассы `hsmd.DispatcherError`. Ошибка во время шага
останавливает диспетчер: конфигурация может быть изменена наполовину,
поэтому каждый вызов порождает `StoppedError` до `restore()`. Упавшее
ограждающее условие — это ошибка, а не ложное условие.

## Сессии

`hsmd_session` предоставляет машину редактору CyberiadaPro. Редактор отмечает
на диаграмме активные состояния и сработавшие переходы, а пользователь делает
шаги, запускает исполнение, посылает события и воспроизводит поток. Протокол
описан в главе «Сессии» документа `PLUGIN-API.md` редактора; это управляемая
сессия (`driven`) с асинхронной логикой.

```
 CyberiadaPro             hsmd_session                  hsmd
 ────────────             ────────────                  ────
 control, event, ─stdin─▶ виртуальные часы,   ────────▶ Dispatcher из
 input, save              поток, посланные              make(**options)
 отметки, история,        события                       step(), tick(run=False),
 вкладка вывода  ◀stdout─ state, history, log ◀─ trace─ states(), triggers()
                          (Log, print: log)
```

```python
import sys

import hsmd
import hsmd_session


def make(**options):
    return hsmd.Dispatcher('coffee.graphml', period=0.1, **options)


sys.exit(hsmd_session.Session(make, period=0.1).serve())
```

| Член | Значение |
|---|---|
| `Session(make, period)` | `make(**options)` возвращает новый `Dispatcher`, построенный с переданными параметрами — `clock`, `calendar`, `trace`, `output`, `input`, `timers`, — в начале и при каждом перезапуске; `period` (секунды) — шаг виртуальных часов |
| `serve(reader=sys.stdin, writer=sys.stdout)` | ведёт сессию до `shutdown` или конца ввода; возвращает код завершения, 0 |

`python -m hsmd_session DOCUMENT [--period S] [--machines A,B]` предоставляет
документ как есть, код диаграммы исполняется в новом пространстве имён.

Ответ на `initialize`:

```json
{"kind": "driven", "logic": "async", "steps": ["event", "input", "time"],
 "speeds": [1, 10, 0], "events": ["..."], "stream": true, "save": true}
```

`events` — это `triggers()` активных состояний.

| Единица, сообщение | Что делает сессия |
|---|---|
| шаг `event` | `step()`: одно событие из очереди; при пустой очереди продвигает часы на `period` с `tick(run=False)`, ставя в очередь наступившие элементы потока, пока не появится событие, но не более `IDLE_PERIODS` (1000) раз, иначе состояние — `waiting` |
| шаг `input` | следующий элемент потока: продвигает часы до его времени, вызывая `tick()` на каждом периоде, посылает элемент и вызывает `run()`; без следующего элемента — как `event` |
| шаг `time` | продвигает часы на `period` и вызывает `tick()` |
| `run` | повторяет `input` (`event`, если потока нет) до `pause`, состояния `finished` или, при скорости 0, до конца потока или `IDLE_PERIODS` без событий; при скорости 1 часы идут вместе с настенными, при N — в N раз быстрее |
| `restart` | новый диспетчер из `make()`, часы на 0, поток с первого элемента, `start()` |
| `event` | `post(name, **parameters)`, значения читаются как в потоке; событие обрабатывается следующим шагом |
| `input` | читает поток и начинает сессию заново с ним |
| `save` | записывает обработанные элементы потока и посланные события с их временем |

* После каждого шага сессия отправляет `state`:
  * `status`: `paused`, `running`, `waiting` или `finished`, когда все машины
    закончились или диспетчер остановлен;
  * `active`: `states()` всех машин;
  * `fired`: записи `fire` шага;
  * `events`: `triggers()`;
  * `time`, `position` и `queue`.
* Каждое обработанное событие — сообщение `history`: имя (пустое для события
  завершения), параметры, время, источник (`input` для элементов потока,
  `user` для посланных событий, `model` для остальных), статус исхода и
  сработавшие переходы.
* Идентификаторы — идентификаторы документа. Внутренний переход `<state>#<n>`
  сообщается как `<state>`, элемент встроенной вложенной машины
  `<state>/<identifier>` — как `<state>`.
* Сообщения `Log` и вывод `print` из кода уходят как `log`. `Console` читает
  пустой ввод, потому что stdin — канал сессии.
* Ошибка останавливает диспетчер. Тогда сессия отправляет `state` `finished`
  с ошибкой в `text` и `log` с уровнем `error`; перезапуск начинает заново.

### Поток

```
# timers: model                       или recorded: Dispatcher(timers=False)
0.000   POWER_ON                      секунды от начала
0.512   button.CLICKED
+0.788  sensor.VALUE value=23.5       секунды после предыдущего элемента
SHOW                                  без времени: сразу после предыдущего
```

* Один элемент на строку; `#` начинает комментарий; пустые строки
  пропускаются.
* Время — одно из:
  * секунды от начала;
  * `+` секунды после предыдущего элемента;
  * дата и время ISO 8601, отсчитываемые от первого из них; тогда `calendar`
    диспетчера начинается с него, и `Clock` видит записанное время.

  Абсолютные времена одного потока — либо все секунды, либо все ISO, и они не
  убывают.
* Значение параметра — литерал Python (`5`, `2.5`, `'a b'`, `True`), иначе
  текст, как в сценариях тестов.
* `# timers: recorded` заставляет сессию строить диспетчер с `timers=False`:
  таймауты и события времени приходят из потока. По умолчанию — `model`.

| Член `hsmd_stream` | Значение |
|---|---|
| `read(text)` | `Stream`: `items` и `timers` (`'model'` или `'recorded'`); неверная строка — `StreamError` с `line` |
| `write(stream)` | текст: время в секундах, три знака после запятой |
| `Item` | `time` (секунды, `None` без времени), `name`, `parameters`, `line` |
